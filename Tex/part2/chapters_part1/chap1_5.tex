\section{Quản lý dữ liệu và phiên bản (Data Version Control - DVC)}
\label{sec:dvc}

Trong phát triển phần mềm truyền thống, Git là công cụ tiêu chuẩn để quản lý phiên bản của mã nguồn. Nó cho phép theo dõi mọi thay đổi, quay lại các phiên bản cũ, và cộng tác hiệu quả.

Trong các dự án học máy, kết quả của một mô hình phụ thuộc vào code và vào ba thứ nữa:
\begin{itemize}
    \item \textbf{Dữ liệu (Data):} Bộ dữ liệu nào đã được sử dụng để huấn luyện?
    \item \textbf{Mô hình (Model):} Trọng số của mô hình được tạo ra từ lần chạy nào?
    \item \textbf{Siêu tham số (Hyperparameters):} Các thiết lập như tốc độ học, kích thước batch là gì?
\end{itemize}

\begin{pitfall}{Vấn đề: “Nó chạy được trên máy của tôi mà!”}
Nếu không có một hệ thống quản lý phiên bản hoàn chỉnh, chúng ta sẽ rơi vào một “địa ngục tái lập” (reproducibility hell). Bạn có thể có một mô hình hoạt động rất tốt, nhưng vài tháng sau, khi dữ liệu thay đổi hoặc một đồng nghiệp muốn tái tạo lại kết quả của bạn, không ai có thể làm được vì không ai biết chính xác phiên bản dữ liệu và các thiết lập nào đã tạo ra mô hình đó.
\end{pitfall}

Git không được thiết kế để xử lý các file lớn như các bộ dữ liệu hay các file trọng số mô hình; commit những file này làm kho Git cồng kềnh và chậm. DVC (Data Version Control) giải quyết đúng chỗ đó.

\subsection{DVC và triết lý hoạt động}
\label{ssec:what_is_dvc}

\textbf{DVC} là một công cụ mã nguồn mở để quản lý phiên bản cho toàn bộ pipeline học máy. Nó hoạt động bên trên Git, không thay thế Git.

\begin{keyidea}{Triết lý của DVC}
Git quản lý phiên bản của các file code nhỏ. Một \textbf{bộ nhớ từ xa (remote storage)} như Amazon S3, Google Cloud Storage hoặc Google Drive lưu các file dữ liệu và mô hình lớn. DVC tạo ra các file metadata nhỏ để theo dõi phiên bản của các file lớn đó, và chính các file metadata này được Git quản lý.
\end{keyidea}

\subsubsection{Cơ chế hoạt động}
Khi bạn muốn theo dõi một file dữ liệu lớn (ví dụ \texttt{data.csv}) bằng DVC, bốn bước sau sẽ xảy ra:
\begin{enumerate}
    \item \textbf{\texttt{dvc add data.csv}:} DVC sao chép file \texttt{data.csv} vào một thư mục ẩn gọi là \texttt{.dvc/cache}, nội dung của file được lưu trữ dựa trên một giá trị băm (hash) duy nhất. DVC tạo ra một file metadata nhỏ tên \texttt{data.csv.dvc}, chỉ chứa thông tin về file gốc, quan trọng nhất là giá trị băm của nó. Cuối cùng, DVC tự động thêm \texttt{data.csv} vào file \texttt{.gitignore} để Git bỏ qua file dữ liệu lớn này.
    \item \textbf{\texttt{git add data.csv.dvc} và \texttt{git commit}:} Bạn commit file \texttt{data.csv.dvc} nhỏ xíu này vào Git. Bất kỳ ai clone kho Git của bạn sẽ có file metadata này.
    \item \textbf{\texttt{dvc push}:} Lệnh này tải nội dung của file dữ liệu thực sự (từ \texttt{.dvc/cache}) lên bộ nhớ từ xa mà bạn đã cấu hình, ví dụ một bucket S3.
    \item \textbf{\texttt{dvc pull}:} Khi một đồng nghiệp clone kho Git, họ không có file \texttt{data.csv}, nhưng họ chạy được lệnh \texttt{dvc pull}. DVC đọc file \texttt{data.csv.dvc}, tìm ra giá trị băm cần thiết, và tải về phiên bản dữ liệu chính xác từ bộ nhớ từ xa vào máy của họ.
\end{enumerate}

\subsection{DVC Pipelines: tái lập toàn bộ thử nghiệm}
\label{ssec:dvc_pipelines}
DVC còn cho phép bạn định nghĩa và kết nối các bước trong pipeline học máy của mình.

\begin{itemize}
    \item \textbf{Định nghĩa các giai đoạn (stages):} Tạo một file (ví dụ \texttt{dvc.yaml}) để định nghĩa các giai đoạn của thử nghiệm, ví dụ \texttt{preprocess}, \texttt{train}, \texttt{evaluate}.
    \item \textbf{Mô tả mỗi giai đoạn} bằng ba trường:
        \begin{itemize}
            \item \texttt{cmd}: lệnh cần chạy (ví dụ \texttt{python train.py}).
            \item \texttt{deps} (dependencies): các file đầu vào của giai đoạn này (ví dụ code \texttt{train.py}, dữ liệu \texttt{data/train.csv}).
            \item \texttt{outs} (outputs): các file được tạo ra bởi giai đoạn này (ví dụ file trọng số \texttt{model.pkl}, file metric \texttt{metrics.json}).
        \end{itemize}
    \item \textbf{Chạy lại pipeline bằng \texttt{dvc repro} (reproduce):} Lệnh này kiểm tra xem có file \texttt{deps} nào đã thay đổi hay không. Nếu có, chẳng hạn bạn sửa một siêu tham số trong code hoặc cập nhật dữ liệu, DVC chạy lại giai đoạn đó và tất cả các giai đoạn phụ thuộc vào nó. Nếu không có gì thay đổi, DVC không chạy lại, nhờ đó tiết kiệm thời gian và tài nguyên tính toán.
\end{itemize}
Bằng cách commit file \texttt{dvc.yaml} và \texttt{dvc.lock} (file ghi lại các giá trị băm chính xác của các deps và outs) vào Git, bạn đã ghi lại toàn bộ “provenance” (nguồn gốc) của một thử nghiệm. Bất kỳ ai cũng có thể checkout một commit Git cụ thể và chạy \texttt{dvc repro} để tái tạo lại chính xác kết quả của bạn.

\subsection{Lợi ích của việc sử dụng DVC}
\begin{itemize}
    \item \textbf{Tính tái lập (Reproducibility):} Đảm bảo rằng các thử nghiệm có thể được tái tạo một cách đáng tin cậy bởi bạn trong tương lai hoặc bởi các đồng nghiệp.
    \item \textbf{Cộng tác:} Các thành viên trong nhóm chia sẻ được dữ liệu và mô hình mà không làm phình to kho Git.
    \item \textbf{Theo dõi thử nghiệm:} DVC cho phép bạn so sánh các kết quả giữa các nhánh Git hoặc các commit khác nhau, nhờ đó thấy được ảnh hưởng của các thay đổi (dữ liệu, code, siêu tham số) đến metric của mô hình.
    \item \textbf{Linh hoạt về lưu trữ:} Hoạt động với nhiều loại backend lưu trữ khác nhau (S3, GCS, Azure Blob, HDFS, SSH, ...).
\end{itemize}
Tích hợp DVC vào quy trình làm việc đòi hỏi một chút nỗ lực ban đầu, nhưng đổi lại là tính ổn định, tính tái lập và khả năng cộng tác về lâu dài.
