\section{Tối ưu hóa mô hình với các thư viện sẵn có}
\label{sec:model_optimization_libraries}
Phần 1 (mục \ref{sec:model_optimization}) đã trình bày lý thuyết của lượng tử hóa và PEFT. Mục này điểm qua các thư viện cụ thể để áp dụng chúng.

\paragraph{bitsandbytes}
Thư viện này phụ trách việc \textbf{lượng tử hóa (quantization)}. Nó cung cấp các kernel CUDA được tối ưu để thực hiện các phép toán trên các định dạng số có độ chính xác thấp, và là thư viện đứng sau \textbf{QLoRA}: lượng tử hóa 8-bit và 4-bit, bao gồm cả định dạng NF4. Với \texttt{transformers}, việc lượng tử hóa một mô hình ngay khi tải về chỉ cần thêm một đối tượng cấu hình.

\begin{example}{Tải mô hình với lượng tử hóa 4-bit (NF4)}{ex:load_llama_4bit}
    \begin{minted}{python}
    import torch
    from transformers import AutoModelForCausalLM, BitsAndBytesConfig

    model_id = "Qwen/Qwen3-8B"

    # Lưu ý: tham số load_in_4bit=True truyền thẳng vào from_pretrained
    # đã lỗi thời; hãy dùng BitsAndBytesConfig.
    bnb_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",        # NormalFloat 4-bit
        bnb_4bit_use_double_quant=True,   # lượng tử kép, tiết kiệm thêm
        bnb_4bit_compute_dtype=torch.bfloat16,
    )

    model = AutoModelForCausalLM.from_pretrained(
        model_id,
        quantization_config=bnb_config,
        device_map="auto",  # Tự động phân bổ các lớp lên GPU/CPU
    )
    \end{minted}
\end{example}

\texttt{bitsandbytes} giảm đáng kể yêu cầu VRAM, nên rất cần khi làm việc với các LLM lớn trên phần cứng hạn chế.

\paragraph{PEFT (Parameter-Efficient Fine-Tuning)}
Thư viện \texttt{peft} của Hugging Face cung cấp các cách triển khai tiêu chuẩn cho nhiều phương pháp PEFT, phổ biến nhất là \textbf{LoRA} (và do đó là QLoRA), ngoài ra có Prompt-Tuning, Prefix-Tuning và Adapter-tuning. Cách dùng LoRA cùng với \texttt{transformers}:

\begin{example}{Sử dụng LoRA với PEFT}{ex:lora_peft}
    \begin{minted}{python}
    from peft import LoraConfig, get_peft_model
    from transformers import AutoModelForCausalLM

    # Tải mô hình gốc
    model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-8B")

    # Định nghĩa cấu hình LoRA
    config = LoraConfig(
        r=8,                 # Thứ hạng (rank)
        lora_alpha=16,       # Hệ số tỷ lệ thực tế là alpha / r
        target_modules="all-linear",  # Khuyến nghị: mọi lớp tuyến tính
        lora_dropout=0.05,
        task_type="CAUSAL_LM",
        # use_dora=True,     # Bật DoRA nếu muốn (xem lý thuyết ở Phần 1)
    )

    # Bọc mô hình gốc bằng PEFT
    peft_model = get_peft_model(model, config)

    # Bây giờ, khi huấn luyện `peft_model`, chỉ các tham số LoRA
    # mới được cập nhật.
    peft_model.print_trainable_parameters()
    # Output dạng: trainable params: ... || all params: ... || trainable%: <1%
    \end{minted}
\end{example}

Kết hợp ví dụ này với lượng tử hóa 4-bit ở trên chính là \textbf{QLoRA}. Trong thực tế, thay vì tự ghép \texttt{transformers} + \texttt{peft} + \texttt{bitsandbytes}, hãy dùng \texttt{SFTTrainer} của TRL (mục~\ref{sec:posttraining_trl}): nó nhận thẳng \texttt{peft\_config} và \texttt{quantization\_config}.

\paragraph{Lượng tử hóa cho phục vụ: AWQ, GPTQ và FP8}
\begin{itemize}
	\item \textbf{Khác biệt quan trọng:} \texttt{bitsandbytes} (NF4) được thiết kế cho \emph{huấn luyện} tiết kiệm bộ nhớ (QLoRA). Để \emph{phục vụ} nhanh, hãy dùng các checkpoint đã lượng tử bằng \textbf{AWQ} hoặc \textbf{GPTQ} (mục~\ref{sec:llm_quantization}), vốn có nhân tính toán được tối ưu trong vLLM và SGLang.
	\item \textbf{Cách dùng đơn giản nhất:} Nhiều mô hình phổ biến đã có sẵn bản AWQ/GPTQ trên Hugging Face Hub; chỉ cần trỏ vLLM tới repo đó. Nếu cần tự lượng tử hóa mô hình của mình, dùng thư viện \texttt{llm-compressor} (họ vLLM) hoặc \texttt{autoawq}/\texttt{gptqmodel} với một tập hiệu chỉnh vài trăm mẫu \emph{thuộc miền dữ liệu của bạn}.
	\item \textbf{GPU thế hệ mới:} Trên H100 trở lên, \textbf{FP8} (W8A8) thường là lựa chọn tốt nhất: gần như không mất chất lượng và được phần cứng hỗ trợ trực tiếp.
	\item \textbf{Luôn đo lại:} Sau khi lượng tử hóa, chạy lại bộ đánh giá của bạn (mục~\ref{sec:lm_eval_practice}) -- suy giảm thường rõ nhất ở suy luận toán, sinh mã và ngữ cảnh dài.
\end{itemize}

\paragraph{ONNX (Open Neural Network Exchange)}
ONNX không phải là một thư viện tối ưu hóa, mà là một \textbf{định dạng file trung gian theo tiêu chuẩn mở}: ta “export” một mô hình từ một framework (như PyTorch) sang định dạng này. Mục đích là khả chuyển (portability) và tăng tốc suy luận (inference acceleration).

Về khả chuyển, một mô hình ONNX chạy được trên nhiều nền tảng phần cứng và phần mềm khác nhau (web, mobile, server) thông qua một \textbf{ONNX Runtime}. Về tốc độ, các ONNX Runtime (ví dụ: ONNX Runtime của Microsoft) áp dụng các kỹ thuật như “graph fusion” (gộp nhiều phép toán nhỏ thành một phép toán lớn) và lượng tử hóa, nhờ đó chạy mô hình nhanh hơn đáng kể so với môi trường PyTorch gốc.
